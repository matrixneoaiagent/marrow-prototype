# Pre-registration — Marrow prototype, Listing 65

This file records the rules used for the final held-out run.  It was written
before the final verification run.  The generator is deterministic, and the
test split is loaded only after the threshold lock is written.

## Targets

| quantity | target | why |
|---|---|---|
| false-accept rate (FAR) | ≤ 5% | a stranger should rarely open the profile |
| false-reject rate (FRR) | ≤ 20% | a tired owner should usually still open it |
| mimic FAR | ≤ 15% | a habit-copying impostor should not walk in |
| swap accepts | 0 | a profile trained on someone else must not open for the owner |

These are prototype targets, not a security guarantee.

## Threshold rule (fixed in code)

The accept threshold is chosen on the **validation split only**:

1. Score every validation session for each owner profile.
2. Pool the owner's validation sessions as positives and all other identities'
   validation sessions as negatives.
3. Candidate thresholds are the observed scores and the midpoints between
   adjacent scores.
4. Choose the candidate that maximises the true-accept rate subject to
   empirical validation FAR ≤ 5%.  Ties go to the higher (more conservative)
   threshold.
5. Write the threshold, the validation file hashes, the code hashes and the
   per-profile shape gates to `artifacts/threshold_lock.json`.
6. Only then load the test recordings.

The numeric threshold is therefore data-dependent, but the *rule* is fixed
before any test score is computed.  It is not moved after seeing test results.

## Shape gate

Each profile also has a two-sided gate on a fixed panel of dispersion/shape
features (straightness, curvature, jerk, dwell variability, pause variability,
stroke-speed variability, intra-burst rhythm, burst-length variability,
correction ratio).  The gate is set from the owner's validation sessions:
`max(3.8, 90th percentile of the owner's top-two robust z + 0.40)`.  A session
far outside the owner's range in either direction is rejected, because both
"too regular" and "too noisy" are departures.

## Swap rule

For each owner, a separate profile is trained on the same-style other person.
The owner is excluded from the swap profile's positives and from its training
and validation negatives.  The swap profile's threshold is chosen by the same
validation rule, then increased by a fixed **0.10 safety margin** before the
swap test.  The margin is part of the rule and is not tuned on the owner's
scores.  The swap test is reported as `opens / owner sessions`, together with
the raw count before the margin.  The raw number is diagnostic only; the
condition is judged on the locked rule.

## Reporting

All counts, confidence intervals and per-style rows are reported whether they
meet the targets or not.  The program exits 0 only if all five listing
conditions pass and the pre-registered targets pass; otherwise it prints the
misses and exits 1.

## Scope

The data are synthetic and generated by `marrow/synth.py` from a public seed.
No real person's movement, text, audio or camera data is used.  Results on this
corpus are not a claim of real-world biometric security; they show that the
method, its thresholds and its failure modes are reproducible.
